# WP7 — Code Quality & Validation Architecture

## Goals

WP7 reduces duplicate implementations, makes the test surface explicit, and separates **validation** from **generated build output**.

It does not change automatic-execution policy. Automatic execution remains OFF.

## Central Node validation suite

The authoritative non-mutating Node test manifest is:

`config/node-validation-suite.json`

`npm test` now runs:

1. `scripts/run-node-validation-suite.js`
2. `scripts/static-quality-validation.js`

The runner executes every listed validation in a fixed order and hashes protected production-state files before and after the suite. A validation that mutates decision/evidence/market state causes the test suite to fail.

This closes the previous gap where several repository tests existed but were not part of `npm test`.

The suite now includes, among others:

- runtime/atomic/UCP validations;
- quant contract validation;
- local server and recommendations PWA validation;
- execution-contract parity;
- output ownership;
- source health;
- calibration governance;
- Final Decision Score robustness;
- decision-cockpit validation;
- Confluence V1/V2 validations;
- WP1 ledger synthetic validation;
- dashboard/runtime legacy tests;
- EGX connector snapshot test;
- shared technical-indicator validation.

## No Vitest dependency for one legacy test

`tests/egx-connector-pipeline.test.js` previously referenced Vitest even though the repository did not install it.

WP7 converts that test to a dependency-free Node test while retaining validation of the ESM market-snapshot module.

## Shared Node technical indicators

Before WP7, the static technical builder and `/api/stock-analysis` separately implemented:

- mean/std;
- EMA;
- RSI;
- ATR;
- linear regression channel;
- pivot detection;
- support/resistance clustering;
- technical assessment.

Those implementations are now centralized in:

`scripts/lib/technical-indicators.js`

Both:

- `scripts/build-technical-analysis.js`
- `app/api/stock-analysis.js`

use the same module.

`scripts/technical-indicators-validation.js` tests the shared implementation and fails if duplicate indicator functions are reintroduced into either consumer.

## Static quality gate

`scripts/static-quality-validation.js` performs dependency-free checks:

- parses repository JSON files;
- runs Node syntax checking across CommonJS server/engine scripts;
- verifies generated-output ignore policy.

Python syntax is additionally checked through:

`python -m compileall -q quant`

as part of `npm run quant:test`.

## Generated-output policy

The following are reproducible build/audit artifacts and are now explicitly ignored:

- `data/technical/`
- `docs/data/technical/`
- `data/release-hardening-report.json`
- `docs/data/release-hardening-report.json`

They are regenerated by build/audit workflows and must not create persistent dirty-worktree noise.

Canonical evidence/ledger/decision files remain tracked and are **not** ignored.

## Build guard

`scripts/build-check.js` now requires the shared technical module, centralized validation runner, static-quality gate and validation manifest.

## Safety

This package is code-quality infrastructure. It does not loosen strategy thresholds, fabricate evidence, or enable automatic orders.
